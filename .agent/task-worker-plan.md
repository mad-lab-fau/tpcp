# Task worker implementation

The imported prototype ends at c5e4e58. The synchronous APIs retain their existing entry points. Configure Task or CachedTask first, then bind its arguments. Task detects coroutine functions. BoundTask carries the result type. Old experimental args/kwargs construction and direct awaiting still work.

Worker.prepare snapshots the manual scope, enclosing subtask claims and the resolved arguments. Treat arguments as immutable after preparation. Worker.acquire returns a Decision with a TaskRecord. Worker.run executes the acquired attempt and renews its lease. Worker.result loads the completed artifact or waits for another participant. ClaimLostError signals that the caller should reacquire or re-enter its enclosing subtask. High-level execute retries failed remote attempts. Caller cancellation leaves shared high-level computations running through Worker exit.

Both storage implementations use SQLite transactions, with one locked in-memory connection or an independent file connection per transaction. Storage transactions serialize ownership changes and check all enclosing scope attempts. A thread stages serialization in the Memory filesystem before a fenced transaction renames the finished artifact. Choose a lease longer than coordinator pauses and filesystem operations. Callers making explicit low-level claims control their own admission.

Ordinary task identity includes the nested manual scope, Memory location, function ID and joblib argument hash. CachedTask uses the original joblib cache key without the manual scope and publishes under its independent lease. Processes must agree on code and environment. The lease protocol applies to participating Workers. Plain Memory callers can populate the same entry concurrently. Retained records and artifacts require explicit removal. SQLite coordinates processes on a single machine. A server database would be needed for distributed coordination.

Overlapping Workers use identical pool options and share admission budgets and GPU IDs across event loops. Legacy execution contexts still require one event loop. No task ancestry is added to a scope. Multiple top-level coarse scopes are admitted up to the local process budget. An acquired nested subtask reuses its enclosing admission. A non-owner that loses its peer can re-enter the subtask after ClaimLostError.
